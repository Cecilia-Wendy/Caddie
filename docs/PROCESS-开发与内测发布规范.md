# Caddie 开发与内测发布规范

## 一套产品，两个动作

Caddie 只维护一套产品功能。托管 AI Gateway、MCP、外部 Agent 和业务功能都归正式主线管理。Hosted Alpha 不是另一款产品，只保留旧 Bundle ID、旧数据目录和旧更新通道等兼容配置，保证现有内测用户可以原地升级。

### 动作一：提交

用户说“提交一下”时：

1. 完成当前小功能并自测。
2. 提交到正式版 Git 分支。
3. 不提升公开版本号，不构建安装包，不影响内测用户。

### 动作二：发布给内测用户

用户说“把今天的更新发布给内测用户”时：

1. 汇总当天正式版提交。
2. 将正式版功能同步到 Hosted Alpha，保留兼容配置。
3. 检查两个目录没有遗漏或半成品。
4. 运行导入、单元测试和关键流程回归。
5. 提升 Hosted Alpha 版本号。
6. 构建并签名安装包。
7. 人工确认更新说明和安装包后再发布。
8. 上传 GitHub Release，并覆盖稳定更新清单。
9. 用旧版客户端验证“发现更新、下载、安装、数据保留”。

## 固定命令

在 `Caddie-Hosted-Alpha` 目录运行：

```bash
# 只检查环境，不修改任何内容
.venv/bin/python scripts/release-hosted-alpha.py check

# 测试、构建、签名，但不发布
.venv/bin/python scripts/release-hosted-alpha.py prepare \
  --version 0.2.6-hosted-alpha \
  --notes "优化资料导入；修复日历同步；完善更新提示"

# 确认安装包和版本提交后，才真正影响用户
.venv/bin/python scripts/release-hosted-alpha.py publish \
  --notes "优化资料导入；修复日历同步；完善更新提示"
```

## 发布闸门

以下任一条件不满足，禁止发布：

- 存在未提交改动或未知文件。
- 正式版功能尚未同步到 Hosted Alpha。
- 测试失败。
- 版本号没有递增。
- 安装包、SHA-256 或 Ed25519 签名缺失。
- GitHub CLI 未登录。
- 更新清单不是 HTTPS 地址。
- 尚未验证旧版本数据保留。

## 版本节奏

- 日常小功能按天合并发布一次，例如 `0.2.5` 到 `0.2.6`。
- 阻断使用的问题可单独发紧急修复版。
- 单个文案或低影响视觉调整通常等到当天集中发布。
- 未完成的功能留在开发提交中，不进入内测更新包。

## 用户侧体验

内测用户只需要打开原来的 Caddie Hosted Alpha，点击顶部更新提示或进入“设置 -> 应用更新”。不要要求用户卸载、安装正式版或重新导入资料。
